**日期**: 2026-06-22

## 1. 需求概述

在现有「今天吃什么」食物抽奖选择器基础上，拆分为两份独立餐谱：

- **🍚 日常**：日常用餐的随机选择
- **🥘 改善伙食**：改善伙食/特殊场合的随机选择

两份餐谱各自拥有独立的食物清单和抽奖功能。

---

## 2. 布局结构

### 桌面端（≥768px）

左右并排两个独立区域，利用现有 sticky 定位。

```
┌──────────────────────────────────────────┐
│           🍜 今天吃什么 — 选择困难症终结者   │
├────────────────────┬─────────────────────┤
│   🍚 日常          │   🥘 改善伙食         │
│   [抽奖框]         │   [抽奖框]           │
│   [开抽按钮]       │   [开抽按钮]         │
│   [食物清单+添加]   │   [食物清单+添加]    │
└────────────────────┴─────────────────────┘
```

### 手机端（<768px）

上下堆叠，日常在上、改善在下。

## 4. 数据存储

使用两个独立的 `localStorage` key：

- 日常：`food-list-daily`
- 改善伙食：`food-list-premium`

原有 `food-list` key 的数据迁移到 `food-list-daily`，实现向后兼容。

### 默认食物

| 餐谱 | 默认食物 |
|------|----------|
| 日常 | 兰州拉面、黄焖鸡米饭、沙县小吃、麦当劳、麻辣烫 |
| 改善伙食 | （空，用户自行添加） |

---

## 5. 功能行为

- 每个餐谱独立增/删/改食物
- 每个餐谱独立抽奖（各自的滚动动画和 confetti）
- 两个餐谱可同时存在不同数量的食物，互不影响
- 键盘快捷键（空格/回车）仅触发当前活跃或第一个区域的抽奖 — 手机端可分别点击各自的按钮
- Toast 提示、Modal 弹窗等通用组件共用
- Modal 标题区分餐谱（如「添加食物 — 日常」）

---

## 6. 实现策略

### HTML 结构

- 在 `<main>` 内将现有单一 `lottery-section` + `list-section` 复制为两份
- 每份包裹在一个带标识 class 的容器中（如 `.menu-panel[data-menu="daily"]`）
- 为每个区域的交互元素赋予唯一 ID

### JS 逻辑

- 重构 `foods` 为对象：`{ daily: [...], premium: [...] }`
- 抽奖/渲染函数接受 `menuKey` 参数
- Modal 打开时记录当前操作的 `menuKey`
- 数据迁移：首次加载时检测旧 `food-list` key 并迁移到 `food-list-daily`

### CSS

- 使用 CSS 自定义属性（或直接覆写）来控制两个区域的颜色差异
- 复用现有动画和过渡效果

---

## 7. 不做（YAGNI）

- 不在两个餐谱之间移动/复制食物
- 不同时抽两个餐谱
- 不添加餐谱自定义命名功能
- 不添加更多餐谱（超过两个）
